Advanced

This page can destroy plugin data. Read before you press anything.
  • Rebuild Store and Delete All Mappings empty the index. A scan rebuilds it, but you wait for the scan.
  • Reset All Data Overrides throws away every edit and deletion you have made.
  • Restore overwrites the index and every mapping with the contents of a backup. Anything edited since that backup was made is gone.
  • Download a plugin backup from this page before you change anything here.

None of this touches your media files or Jellyfin's own database. The worst case here is a lost index, which a scan rebuilds from the files.

Removes every edit and deletion you have made to indexed values, and restores everything from your files on the next scan. Mappings are not affected.

Backups

Backup and restore are paused. A scan or an update is running, so the index is being written to. A copy taken now could catch it half-written, and a restore could be overwritten by the write still in flight. Both resume on their own when the activity stops.
What a backup contains
One zip holding the whole index database, that database's write-ahead file, and a copy of your mappings. The two database files belong together — do not unpack and split them. This is the only complete snapshot the plugin can take.

Restore

Restoring replaces everything
The current index and all mappings are overwritten by the contents of the zip. A scan can rebuild the index from your files, but any edits or deletions you made to indexed values are lost with the old index.
Backup file
Choose a zip made by Download Backup above, or a .db file such as one of the pre-restore copies. Before anything is replaced the current index is copied into the store folder as pre-restore-…db, so a restore can be undone; only the three most recent of those are kept.
If the counts on this page look wrong straight after a restore, restart Jellyfin so the database is reopened cleanly. You can do that here.
